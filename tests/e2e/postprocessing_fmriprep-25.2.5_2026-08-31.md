# Postprocessing E2E evidence: fMRIPrep 25.2.5

## Verdict

**PASS**. The run exposed one dependency-packaging gap and one transform-metadata
defect; both are resolved in the 0.9-2 release candidate as described below.

On 2026-08-31, the complete configured post-fMRIPrep workflow was run for
`sub-540294` against derivatives generated by fMRIPrep 25.2.5. The run used
the full-length 4D inputs: one rest run with 628 input volumes and four task
runs with 1,301, 1,259, 1,265, and 1,269 volumes. No runs were shortened.

All five pipelines reached their intended final outputs. All 28 enabled
postprocessing validation checks passed (28 passed, 0 failed, 0 errored, and
0 skipped), and task ROI extraction completed with valid time series,
diagnostics, and connectivity outputs for all four task runs.

This evidence supports the production behavior of the configured checks on
these data. It is an E2E regression result, not a claim that one subject spans
all possible acquisition protocols or calibration support.

## Defects and qualifications exposed by the run

### Template-mask transform metadata

Two preliminary strict attempts correctly failed at `apply_mask`: nilearn
resampling preserved array dimensions, voxel sizes, and affine matrices but
changed target qform/sform codes from 4/4 to 0/2. Before the successful E2E,
the working tree was patched to preserve the target BOLD qform and sform
matrices and codes and to invalidate stale cached resampled masks. A focused
regression test using a synthetic target with qform/sform codes 4/4 passed
11/11 expectations. The successful E2E confirmed 4/4 in all final headers.

The successful run therefore used base commit `bf4da4a` plus the uncommitted
changes in:

- `R/postprocess_functions.R`
- `inst/fetch_matched_template_image.py`
- `tests/testthat/test-resample_template_fallback.R`

The SHA-256 of the combined patch from
`git diff -- R/postprocess_functions.R inst/fetch_matched_template_image.py tests/testthat/test-resample_template_fallback.R`
was:

`e52377c58e584e1f6d5d6adbb42f4346ac0603f11a7d3673cfafc954ffd740bf`

The patch and its regression tests were committed in `9fa6e3f`. The 0.9-2
release candidate therefore contains the behavior exercised by the successful
E2E run.

### Temporal-validation dependency

The run initially found that `signal` was imported while `multitaper` was only
suggested even though temporal-filter validation requires both packages. The
0.9-2 release candidate promotes `multitaper` to `Imports`, so an ordinary
installation supplies the validation dependency. The numerical E2E results
remain those obtained after that dependency was made available in the isolated
test library.
